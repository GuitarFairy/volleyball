첨부한 hwaiq-volleyball-codex.zip을 풀고 기존 화이큐 9인제 배구 기록 시스템을 GitHub + Cloudflare에 운영 배포해줘. 프로젝트를 새로 만들지 말고 현재 코드와 디자인을 유지해.

먼저 CODEx_DEPLOY.md, AUTH_HANDOFF.md, HANDOFF.md를 읽고 npm test를 실행해. dist는 현재 정적 앱의 실제 소스이며 빌드 산출물로 착각해서 지우면 안 돼.

목표는 로그인한 허용 사용자만 우리 팀 기록을 보고 입력할 수 있고, 다른 기기에서도 같은 경기 기록을 이어서 볼 수 있는 운영 서비스야. 현재는 LocalStorage 데모라서 배포만으로 로그인/공유 저장이 완성되지 않아. 서버 세션 인증과 Cloudflare D1/API 저장소까지 연결해. 가능한 가장 단순한 Cloudflare Worker + 정적 assets 구성을 사용하고 사용자 승인/허용 목록으로 화이큐 팀 접근을 제한해. 실제 인증 제공자는 현재 사용 가능한 계정/서비스를 확인한 뒤 구현해. 프런트 숨김이나 LocalStorage 로그인 토큰으로 접근 보호를 흉내 내지 마.

반드시 유지할 기능:
- 9인제 코트 최대 9명 + 제한 없는 대기 선수, 세트별 독립 setRosters/포지션/순서와 엔트리·대기 교환
- Excel형 모든 열, 고정 이름/헤더, 좌클릭 +1·우클릭 -1·직접 숫자 입력·Undo·팀 합산·기존 calculations.js 수식
- AL/AM(오버/언더) 셀 옆 공격수 선택 박스. 자기 자신 제외, 포지션 배지, 선택하면 source 유형 +1 및 target P +1, 공격수 강조
- set.settingLinks, game.setNotes, 과거 setRosters/raw 및 선수 스냅샷 보존
- 선수 체크박스 삭제/soft delete, 경기 삭제, 경기 결과, 통계/전술 분석/세팅 분석
- 5판 3선승·3판 2선승·단판

repository 접근 계층을 API 구현으로 교체하되 기능 코드를 여기저기 바꾸지 마. 데이터는 team/user 권한을 갖고 Player/Game/GamePlayer/Set/PlayerSetStats와 settingLinks/메모를 빠짐없이 보존해. 퍼센트는 raw로 계산하고 DB 중복 저장하지 마. 숫자 연속 클릭을 debounce로 누락시키지 마. 서버 저장은 원자적 처리/동시 수정 검증을 하고 실패하면 저장 실패를 분명히 표시해. 기존 기록원 UX가 느려지지 않게 해.

기존 브라우저 기록은 소스 ZIP에 포함되지 않아. 운영 데이터로 가져올 수 있는 안전한 백업/가져오기 경로를 만들고 본인 확인 후 명시적 가져오기를 지원해. 기존 LocalStorage를 자동 삭제하지 마.

실제 GitHub 저장소 생성과 Cloudflare 배포까지 진행해. 기존 .openai/hosting.json은 Work 사이트 정보이므로 운영 Cloudflare 설정과 분리하고 기존 Work 사이트를 변경하지 마. 비밀 값은 커밋하지 말고 서버 secret로 저장해. 로그인/접근 제한이 서버에서 검증되기 전에는 운영 기록을 공개하지 마. 필요한 계정 인증은 사용자가 직접 연결하도록 안내하되, 구현과 테스트를 먼저 최대한 끝내.

테스트: 선수12명→코트9/대기3, 2세트 독립 교체/포지션/순서, 대기 합산, 오버/언더 연결 및 자기 제외/우클릭/Undo, 메모 재접속, 종료 전적·통계, 선수/경기 삭제, 비로그인 직접 URL/API 차단, 비허용 로그인 403, 로그아웃/만료/계정 전환, 다른 기기 기록 복원. 세팅 분석의 공격수별 득점률은 유형 링크만으로 추정하지 마. 기존 브라우저 UI 테스트는 실행 환경을 점검하고 최신 UI에 맞춰 보완해.

완료하면 실제 운영 URL, GitHub 저장소 URL, 인증 방식, DB 마이그레이션/백업/복구 방법과 남은 제한사항을 간단히 보고해.
